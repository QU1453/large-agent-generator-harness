# WiFi 团队开发（设计方案）

> 需求（8/20）：在 harness 内做"团队开发"——同一 WiFi/局域网内的成员连接运行中的 LAG harness 协作。
> 状态：**✅ 已全流程开发完成并打包 release（8/20）**：team.js 仓库 → api-server 团队路由 + team-web.html 控制台 → main.js/preload IPC → TeamPanel + 侧栏 → 验证（单测 17 项 + dev e2e 29 项 + 打包版冒烟 16 项 ALL_OK）。**8/20 补充：资产传输（成员 📥 下载 / 📤 上传智能体·工具·工作流·技能）+ Python 运行时全零字节修复（`scripts/repair-extra-resources.mjs`）**。约束：所有开发/测试/打包均在 `D:\Project\Harness` 项目内，不碰 D 盘项目外文件、不写 C 盘。

---

## 一、目标与形态

| 诉求 | 现状 | 目标 |
|------|------|------|
| 团队协作 | 外部 API 只监听 127.0.0.1，仅本机工具调用 | harness 内一键启动**团队服务**（监听 0.0.0.0），同一 WiFi 内成员用**浏览器**访问团队控制台，无需安装 |
| 成员沟通 | 无 | 团队成员在线列表 + **团队频道**（文本消息 + `@ai` 托管给智能体回复） |
| 共享资产 | 无 | 成员可浏览主机的智能体/工作流/记忆列表（只读），在频道里发消息驱动主机智能体 |

**三条底线**（同记忆/工作流）：
1. 不启用团队服务 → 行为与现在完全一致（外部 API 仍只监听本机）；
2. 团队数据落盘 `data/team.json`（人可读），不引入数据库；
3. 控制台页面单文件内嵌、零外部依赖，离线可打开。

---

## 二、总体结构

```
LAG harness（主机，一台机器）
 ├─ 主进程 api-server（单 http server）
 │    ├─ /api/*   原有外部 API（本机 127.0.0.1，可选 Token）
 │    └─ /team/*  团队路由（0.0.0.0 监听）：控制台页 + JSON API + 频道轮询
 ├─ team.js 团队状态仓库（成员/在线心跳/频道消息/局域网 IP/存储/AI 托管）
 └─ 前端 TeamPanel（侧栏「团队」）：
      开关启动/停止 · 局域网地址(复制) · 成员在线 · 内置团队频道（发消息/@ai）
成员设备（同一 WiFi）
 └─ 浏览器打开 http://<主机IP>:<端口>/team → 输入昵称 → 频道聊天 / 浏览共享资产
```

**地址**：主进程用 `os.networkInterfaces()` 取第一个非内部 IPv4（如 `192.168.x.x`），团队面板显示 `http://192.168.x.x:37800/team`，一键复制。

## 三、数据模型（data/team.json）

```json
{
  "enabled": false,            // 团队服务开关（上次状态）
  "port": 37800,               // 复用外部 API 端口（同一 server）
  "name": "我的团队",           // 团队名（settings.teamName 镜像）
  "members": {                 // 成员（含主机）
    "m-abc123": { "name": "小明", "isHost": true, "joinedAt": 1787000000000, "lastSeen": 1787000000000 }
  },
  "channel": [                 // 最近 200 条频道消息
    { "id": "msg-1", "type": "text", "from": "m-abc123", "name": "小明", "text": "大家好", "ts": 1787000000000 },
    { "id": "msg-2", "type": "ai",   "from": "ai",       "name": "AI",     "text": "回复内容", "ts": 1787000000000 }
  ]
}
```

**在线判定**：成员每次轮询/发消息更新 `lastSeen`；主机状态在 `state` 响应里带 `now`，前端对 `now - lastSeen > 8s` 显示离线（不物理删除，保留最近 20 个成员）。

## 四、接口设计

### 4.1 控制台（浏览器成员）
| 路由 | 方法 | 说明 |
|------|------|------|
| `/team` | GET | 团队控制台页面（team-web.html，单文件原生 JS） |
| `/api/team/join` | POST | `{name}` → 注册成员，返回 `{memberId, name, state}` |
| `/api/team/state` | GET | `?memberId=&since=` → `{now, name, members, channel(增量), agents, workflows, memories}` |
| `/api/team/post` | POST | `{memberId, text}` → 写入频道；`text` 以 `@ai ` 开头 → 托管给主机 assistant，回复写回频道 |
| `/api/team/leave` | POST | `{memberId}` → 标记下线 |

增量：`state` 带 `since`（上次最后一条消息 ts），只返回 `ts > since` 的新消息；members 全量返回（<20 个，量小）。

### 4.2 主机（TeamPanel，IPC）
| IPC | 说明 |
|-----|------|
| `team:start` | 启动团队服务（监听 0.0.0.0；若外部 API 已启用则复用现有 server 只改地址监听） |
| `team:stop` | 停止团队服务（回退 127.0.0.1，外部 API 本机仍可用） |
| `team:status` | `{running, port, url, lanIps}` |
| `team:state` | 当前 `{name, members, channel}`（面板渲染用） |
| `team:post` | 主机在频道发消息（支持 `@ai`） |

### 4.3 资产传输（8/20 补充）
| 接口 | 说明 |
|------|------|
| `GET /api/team/download?kind=&name=` | 主机 → 成员：按类型返回原始内容（agent/mcp=源文件、workflow=store JSON、skill=md 文本） |
| `POST /api/team/upload` | 成员 → 主机：`{memberId, kind, fileName, content}`；**文件名白名单**（`.agent.js/.agent.py/.mcp.js/.mcp.py/.md/.json` + `path.basename` 防路径穿越 + 1MB 上限）→ 保存到主机 data 并 reload → 频道广播「📤 上传了资产」 |

> 协同工作流（"多成员调整同一个工作流"）MVP 路径：成员 📥 下载工作流 JSON → 本地修改 → 📤 上传覆盖（`workflowStore.save` 按 id 覆盖）→ 主机运行即用新版本；成员间无并发冲突管理（轮询架构下做实时协同编辑风险高，列为后续）。

**端口/地址规则**：团队服务与外部 API 共用 `settings.apiPort`（默认 37800）同一 http server；团队模式下 `server.listen(port, '0.0.0.0')`，非团队模式保持 `127.0.0.1`。启动失败（端口占用）→ 面板报错提示。

## 五、控制台页面（team-web.html）

单文件、零依赖、原生 JS，`electron/team-web.html` 打进 asar，api-server 读取返回。
- 进入先输昵称（localStorage 记住）→ `join` 拿 memberId；
- 界面：顶部团队名 + 在线成员数；中间频道消息流（text / ai 消息不同样式）；底部输入框（`@ai 帮我写个函数` 触发智能体托管）；右侧共享资产栏（智能体/工作流/记忆三组只读列表，点击展开描述）；
- 轮询：每 3s `state?since=` 增量拉取；发消息后立即刷新；
- 主题：深色（与 harness 一致的紫色系，手写内联 CSS）。

## 六、AI 托管（@ai）

`team.post` 收到 `@ai <内容>`：
1. 消息先以 `{type:'text', name:'小明', text:'@ai 帮我…'}` 写入频道并广播；
2. 主进程 `chat.runChat`（agent=assistant，settings 全局，工具用默认 assistant 工具）生成回复；
3. 回复以 `{type:'ai', name:'AI', text:回复}` 写回频道广播；
4. 失败 → 写 `{type:'ai', text:'⚠️ AI 回复失败：…'}`，不阻断频道。

## 七、前端 TeamPanel（侧栏「团队」）

- 顶部：团队名（可改，存 settings.teamName）+ 开关（▶ 启动 / ⏹ 停止）+ 地址行（`http://IP:port/team` + 📋 复制）
- 成员区：在线成员徽章列表（主机标 ⭐，离线置灰）
- 频道区：复用 `Message` 风格的气泡列表 + 输入框（`@ai` 提示）+ 发送；主机消息与成员消息同构渲染
- 资产区（可选）：本机智能体/工作流/记忆数量摘要（提示"成员在控制台可见"）
- 启动后面板自动轮询 state 刷新在线/消息（每 3s）
