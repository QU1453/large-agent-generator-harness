# LAG harness 项目文档

> 图形化 LAG（Large Agent Generator）工具：可视化编排多个智能体组成"大型 Agent"，支持工作区、技能、MCP 工具、子工作流，并可导出为免装 Python 的自包含 Agent 包（含一键 exe）。
> 本文档记录项目框架、功能清单、数据存储，以及开发/打包过程中踩过的坑与解决方案。

---

## 1. 技术栈与整体架构

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 桌面壳 | Electron 33 | 主进程 `electron/main.js`，渲染进程加载前端 |
| 前端 | React 18 + Vite 5 | `src/`，组件化界面（侧栏/会话/工作流画布/工作区/设置） |
| 主进程模块 | Node.js（CommonJS） | agents / mcps / chat / workflow / workspace / skills / store / exporter / api-server / tools |
| 通信 | contextBridge + IPC | `electron/preload.js` 暴露 `window.harness.*` |
| 数据 | JSON 文件 | `data/` 目录（可被环境变量 `AI_HARNESS_DATA` 覆盖） |
| 导出运行时 | Python 3.12（内嵌） | `runtime/python`，导出物为自包含 Python 包，PyInstaller 可打成单文件 exe |

### 进程内职责

- **主进程（electron/main.js）**：创建窗口、注册全部 IPC、聊天/工作流/导出的真正执行者、API 服务、数据目录重定向、单实例锁。
- **渲染进程（src/）**：纯 UI。任何"能力"（读文件、跑智能体、跑工作流、导出）都通过 `window.harness.xxx()` 调主进程。
- **Python 引擎（electron/python-engine.js + 导出物 executor/）**：导出的 Agent 包在目标机器上用内嵌 Python 跑同一套图编排逻辑。

### 数据流示例（一次对话）

```
用户输入 → ChatView → h.chat.send() → main: chat:send IPC → chat.runChat()
        → LLM 流式 token → main: chat:token → 渲染进程流式回显
        → 完成后 chat:done（含思考痕迹 trace）→ 消息落盘 data/sessions/<id>.json
```

## 3. 功能清单

### 3.1 会话与聊天
- 多会话列表，会话可绑定目标：**智能体**（单智能体对话）或**大型智能体（工作流）**（消息灌入工作流输入节点运行）。
- 流式输出、停止生成、思考痕迹（`trace`：工具调用记录 / 工作流节点进度）。
- 每个会话可独立覆盖模型（datalist 预置模型）。

### 3.2 智能体 / MCP 工具
- 智能体 = `.agent.js` / `.agent.py` 代码文件，含 systemPrompt、tools、model 覆盖等。
- 工具/MCP = `.mcp.js` / `.mcp.py` 工具包，可被智能体通过 `mcp:工具名` 引用。
- 分类文件夹管理、代码编辑器（内嵌）。

### 3.3 技能（Skills）
- 技能 = `data/skills/<name>.md`（首行 `# 标题`，正文即指令）。
- 独立管理页（列表/新建/编辑/删除）；在工作流智能体节点上可"链接技能"，执行时把技能正文注入该节点 system prompt。

### 3.4 工作区（多 Sandbox）
- 左侧「工作区」栏每项 = 一个 sandbox（`data/sandboxes.json`），可 **＋ 新建 / 切换 / 🗑 删除**（删除仅移除记录，不删文件夹）。
- 每个 sandbox 绑定独立文件夹 + **独立聊天记录**（`sandbox.sessionId`）。
- 工作区页可：新建、切换文件夹（`sandboxSetRoot`，不产生重复条目）、切换、删除。
- 文件树浏览 / 内嵌编辑 / 重命名 / 删除 / 新建文件目录（受 `safeResolve` 越界保护）。
- 底部「工作区对话」随 sandbox 切换加载各自会话。

### 3.5 工作流（核心）
- 节点类型：**输入 / 智能体 / 子工作流 / 输出**。
- **自定义输入/输出**：输入、输出节点与智能体一样可内嵌工具/技能/记忆（上下端点 + 框内 🔧/🎯/🧠 罗列 + 缩放柄）。链接了工具/技能/记忆的节点，运行时由**默认智能体 assistant** 加工处理（输入节点加工节点文本，输出节点加工上游结果；工具并集 + 技能注入 + 记忆工具绑定），未链接则保持原行为（输入=纯文本透传，输出=上游拼接）。
- 连线语义：`from 输出 → to 输入`，执行按 Kahn 拓扑排序。
- 区域总线：`[[区域名]] ... [[/区域名]]` 文本标记，节点通过 `readZones/writeZones` 控制读写权限。
- 智能体节点：选智能体、附加指令、区域权限、**🔧 链接工具（内置/MCP）/ 🎯 链接技能 / 🧠 链接记忆**。
- 智能体节点**上方紫色端点 = 链接 MCP/内置工具，下方橙色端点 = 链接技能**（快捷入口）。
- **右键智能体节点菜单含「✏ 编辑智能体代码」**：直接打开该智能体的源码编辑器（复用 CodeEditor，保存后自动重载）。
- 子工作流节点：选择另一个工作流，上游内容灌入子工作流，输出回传；共享调用栈防循环引用（允许菱形引用）。
- 画布交互：左键选/拖节点，**左键空白拉框框选（多选后整体拖动、Delete 删除选中组）**，**中键拖拽平移画布**，滚轮缩放，右键三态菜单，小地图，Ctrl+S 保存。
- **视口位置持久化**：画布平移/缩放位置按工作流 id 存 localStorage（`wf-view:<id>`），切出再打开自动恢复，不用每次移动窗口；新建工作流重置为默认。
- **画布大小**：工具栏可设置画布宽 × 高（节点超出画布会自动扩展 world 尺寸）。
- **智能体框可缩放**：节点右下角 `.wf-resize` 手柄拖拽改宽高（最小 170×110），输出端口位置随缩放宽度自适应。
- **内嵌工具/技能/记忆罗列**：智能体框内「🔧 工具」「🎯 技能」「🧠 记忆」三组（工具+技能并排一行、记忆独占一行），各含标题 + ＋添加 + 逐项 [图标+名称][✕移除]；技能显示标题（skillList 匹配）、记忆显示标题（memoryList 匹配）。
- **节点链接记忆架构**：智能体/输入/输出节点可链接记忆架构，运行时获得 `memory_read / memory_write / memory_append` 三个工具（绑定所选记忆文件）+ system 说明注入；记忆跨运行保留，导出时随 LA 包固化（engine.py `_bind_memory` 合并记忆工具 + `memory/<架构>.md` 复制）。
- 运行状态**全局**：切页不中断（运行在主进程），侧栏「工作流/工作区」旁转圈指示，节点状态全局保存、切回可恢复。

### 3.6 导出大型 Agent（LAG）
- 工作流 → 自包含 Python Agent 包：`manifest.json`（契约+智能体+工作流图+子工作流）、`la/`（**Python 库接口**）、`executor/`、`transports/`、`web/` 控制台、`tools/`、内嵌 `runtime/`、`memory/` 记忆空间、技能目录。
- **两种导出形式**（导出弹窗可选，均完整打包、脱离 harness 独立运行）：
  - **Python 库**：`import la; la.La().run("你好")` 直接调用（`la/__init__.py` 封装 `La` 类，读取 `data/config.json` 或实例化传 `config` 覆盖）；
  - **API 服务**：`la_main.py --serve` 启动 HTTP 服务调用（含 token 鉴权 + 自带控制台）。
  - 导出形式 `all`（默认，两种都带）/ `py`（仅库）/ `api`（仅服务），接入说明.md 按所选形式组装调用方式。
- 可选 **PyInstaller 打包为单文件 exe**（免装 Python，双击即用）。

### 3.7 其他
- 外观设置（壁纸：纯色/渐变/图片）、API 服务开关、模型/接口配置。
- **「设置」按钮 = 齿轮图标（SVG 17×17）**，固定在**软件左下角**（侧栏底部 `.sidebar-footer` + `margin-top:auto`），工作流/会话/工作区等任意界面都在同一位置。

### 3.8 记忆（Memory，文档驱动：记忆管理-开发文档.txt + 整体方案.md 第四节 + 记忆架构设计方案.md）
- **记忆架构 = 一个"记忆空间"目录**（md 文件优先，人可读可改，绝不做成黑盒），存储位置：harness 内 `data/memory/<架构名>/`，导出物 `memory/<架构名>/`（随 LA 包整体复制）。
- 目录含五个文件：`policy.md` 场景策略（何时读写/何时遗忘，可编辑）/ `ledger.md` 账本（**只追加**，每次写操作自动留痕，溯源）/ `facts.md` 事实 / `episodes.md` 情景 / `skills.md` 程序性技能 + 可选 `notes/*.md` 自定义记忆文件 / `engine.py` 记忆引擎代码（阶段 B）/ `config.json` 架构差异化配置。旧版单文件记忆（`memory/<name>.md`）启动时自动迁移为目录（内容入 facts）。
- **记忆工作台（阶段 A，已实现）**：记忆页卡片「🧰 打开工作台」→ 三栏工作台（左文件树 / 中 md·代码高亮编辑器 / 右属性面板）；文件树点选即编，`Ctrl+S` 或 💾 保存写盘（ledger 只读）；可新建文件、新建 `engine.py` 模板；顶栏「🧹 整理」（读全部记忆 → 管家/整理工作流去重分类写回）、「📥 提取」（8/21，见下）、「⚙ 配置」（config.json 表单）、「＋ 文件」。
- **任意文件自由增删（8/21，用户要求"不是这么自定义的，要能自由修改记忆卡片里的文件、可新增可删除"）**：`createNote/deleteNote` 只支持 `notes/*.md` → 升级为通用 `createFile(name, rel, content)` / `deleteFile(name, rel)`（`memory:create-file` / `memory:delete-file` IPC）：**任意相对路径**（`notes/待办.md`、`bus.md`、`ideas`、任意子目录），无扩展名自动补 `.md`；删除**仅保护 5 个内置核心文件**（policy/facts/episodes/skills/ledger，可编辑不可删），`engine.py`/`config.json`/`notes/*` 均可删。`listFiles` 改为**递归列出架构目录内全部非内置文件**（不再只列 notes/*.md + engine.py + config.json）。UI「＋ 笔记」→「＋ 文件」**可选择类型 .md / .txt / .py**（输入已有扩展名时以输入为准，8/21 第二轮按用户要求明确支持三种类型）。**删除交互（8/21 第三轮，用户要求"记忆卡片打开后右键点击文件弹出是否删除"）**：文件树项支持**右键菜单**（`.mem-ctx`：标题 + 🗑 删除文件 + 取消），confirm 二次确认后 `deleteFile`。
  - **文件保护机制（8/21 第四轮，用户要求"右键选择是否放入保护/离开保护，受保护则删除键禁用（灰色）"）**：每个文件可独立切换保护状态，存 `config.json` 的 `protected` 数组（相对路径）；`protected` 为 null（未设置）时**内置 5 核心默认受保护**，新文件默认不受保护。受保护文件：文件树 🗑 按钮**禁用（灰色）**、右键菜单"🗑 删除文件"禁用、后端 `deleteFile` 拒绝（兜底）。右键菜单新增「🛡 加入保护 / 🔓 取消保护」切换项（IPC `memory:set-protected`）。取消保护后内置文件即可删除。
- **工作流记忆节点（8/21 第二轮，用户要求"在工作流里加入记忆节点（较大矩形）提供多个读取和写入接口"；第四轮起为工作流中唯一记忆管理方式）**：新增节点类型 `memory`（大矩形，默认 300×250，右键菜单 🧠 记忆 创建）：
  - **数据模型**：`{type:'memory', memoryArch, reads:[{id,label,arch,scope}], writes:[{id,label,arch,scope}], w,h}`；`memoryArch` 为空 = 未指定架构（该节点不执行读写），接口 `arch` 为空 = 使用节点 `memoryArch`。
  - **读取接口**：运行时把各接口指定记忆文件内容读出，拼接为本节点输出（`==== 架构 / scope ====\n内容`），供下游节点使用；**写入接口**：运行时把上游输入**追加**写入各接口指定记忆文件（`ledger` 除外——账本只允许记忆工具自动追加）。
  - **前端**：节点框内两个接口组（📖 读取 / ✍️ 写入）各带 ＋添加 / ✕移除；添加弹窗（名称 / 记忆架构 / scope 支持内置 scope + bus.md + 任意路径 datalist）；有输入/输出端口 + 缩放柄（无工具/技能上下端口）。
  - **引擎（workflow.js）**：`runWorkflowInner` 新增 memory 分支（写 → 读 → 输出），scope 解析 = 内置 5 文件映射或 `memory.resolveInArch` 越界校验；架构只取节点自身 `memoryArch`。
  - **导出（exporter.js）**：`checkWorkflow` 校验读取/写入接口指向的架构（缺失 warning）；`collectMemory` 收集节点 memoryArch + 接口显式 arch（含子工作流递归）；PY_ENGINE `run_graph` 新增 `elif type == 'memory'` 分支（`_mem_file` 内置 scope 映射 + 越界防护，写前 rstrip 追加，跳过 ledger）。
- **记忆工作区绑定（8/21，用户要求"像工作区一样可以添加或删除智能体、工具、skill、通信总线"）**：`config.json` 新增 `agents[] / tools[] / skills[] / bus`（默认 bus 开启）。工作台右侧属性面板新增「绑定（工作区式）」四行：🤖 智能体 / 🔧 工具 / 🎯 技能（各带 ＋ 下拉添加 + ✕ 移除，数据来自 `h.agents.list()` / `h.tools.list()`（内置名 + `mcp:名`）/ `h.skills.list()`）+ 📡 通信总线（开关）。`archBinding(name)` 升级：tools = 五记忆工具 **∪ config.tools**；prompt 注入链接技能正文（`skills.get` 读正文，与工作流节点技能注入一致）、链接智能体协作提示、通信总线说明。
- **通信总线 bus.md（8/21）**：`create()` 时自动生成 `bus.md`（区域语法 `[[区域]]…[[/区域]]`，同工作流通信总线），关闭 `bus=false` 后不再提示。**memory 工具支持自定义 scope**（tools.js `memoryTool`）：`scope` 传任意架构内路径（如 `bus.md` / `notes/xxx.md`）时经 `memory.resolveInArch` 校验后读写（read/write/append/forget 均支持，ledger 仍只读），写操作照常记账本（账本文件名回退显示原 scope）。
- **提取记忆管家（8/21，用户要求"智能体要提取记忆、管理记忆"）**：新增 `memory.runExtract(name, text, opts)`（IPC `memory:extract`）：assistant + 五记忆工具把一段文本（对话记录/长文/纪要）蒸馏写回——偏好/结论写 facts（memory_write）、事件写 episodes（memory_append）、可复用步骤写 skills（memory_write/append scope=skills.md），账本留痕；工作台顶栏「📥 提取」弹窗粘贴文本 → 管家入库。绑定的智能体在会话/工作流中使用该记忆时自动获得 memory_* 工具 + 绑定工具 + 技能正文，并可用 scope=bus.md 读写通信总线。
- **架构差异化配置**（`config.json`）：`defaults.writeScope`（memory_write 默认文件，默认 facts）/ `defaults.appendScope`（memory_append 默认文件，默认 episodes）/ `ledger`（是否记账本）/ `txn`（是否带 [[txn:日期]]）/ `organizeWorkflow`（整理工作流 id，复用工作流引擎；空=默认管家）/ `engine`（引擎代码文件名）。tools.js `memoryTool` 运行时读 config 生效。
- **会话/工作区绑定（阶段 A，已实现）**：会话顶栏 + 工作区对话栏均可绑定一个记忆架构并**锁定**（`sessions:set-memory-arch` / `workspace:sandbox-set-memory-arch`）；冲突规则：**会话优先，未绑定时继承所在工作区的绑定**；绑定记录 `boundAt` + 版本游标 `lastArchMtime`（架构目录 mtime）。
- **更新先整理**：绑定架构被编辑（mtime 变化）后，**下次对话/运行前先自动整理一遍再继续**（`memory.runOrganize`：优先 config.organizeWorkflow 跑工作流，否则默认管家流程=assistant 读全部记忆→去重/分类→memory_* 写回）；整理失败不阻断对话，游标不更新下次再试。
- ~~**工作流级记忆（8/20 第二轮，已实现；8/21 第四轮已移除）**~~：工作流工具栏「🧠 记忆」选择器 + 节点框内「🧠 记忆」链接组 + `manifest.memoryArch` 固化 + PY_ENGINE `_bind_memory` 全部删除——**工作流中记忆管理只保留记忆节点一种方式**（用户 8/21 第四轮："工作流的记忆管理过于混乱，只保留记忆节点这一种"）。会话/工作区绑定记忆（session/sandbox.memoryArch）不受影响。

## 5. 遇到的问题与解决方案（踩坑记录）

### 5.1 打包/发布类
1. **改包前必须先停掉所有 `LAG harness.exe` 进程**（含 GPU/network/renderer 子进程）。否则打包报"文件被占用改不了"。
2. **打包输出目录固定 `release`**，绝不新建 release2/release3 等版本目录。打包命令：
   `npx electron-builder --dir "-c.directories.output=release"`（`-c.xxx` 必须加引号，否则 PowerShell 会当成文件路径）。
3. **TRAE IDE 文件监视器会锁 `release\win-unpacked\resources\app.asar`**：表现是"禁止删除、但允许覆写"（Copy-Item -Force 可覆盖，Remove-Item / node fs.rmSync 均 EPERM），electron-builder 的"先删后写"必然失败。
   **解法**：打包到项目内瞬态目录 `.stage-release`，成功后用
   `robocopy .stage-release\win-unpacked release\win-unpacked /E /IS /IT /NFL /NDL /NJH /NJS`（rc≤7 即成功）覆盖合并，最后删掉 `.stage-release`。最终产物仍在 `release`。
4. **绝不用 `asar extract-file` 提取到项目内路径**：它会把文件写到 cwd 相对路径并覆盖同名真实源码（如 `electron/main.js`）。必须先 `Set-Location` 到临时目录再提取；校验用 `Compare-Object` 对比源文件与打包产物。

### 5.2 数据/文件类
5. **PowerShell `Set-Content -Encoding UTF8` 会写带 BOM 的 UTF-8**，导致 `JSON.parse` 失败（工作流列表少一个）。写 JSON 一律用 node 或 `[System.IO.File]::WriteAllText`（无 BOM）。
6. **工作流文件名必须等于其 id**（`workflows/<id>.json`），否则 `get(id)` 返回 null 而 list 正常（UI 显示空白画布）。
7. **测试数据目录放项目外**（如 `$env:TEMP\lag-test`）：Vite dev server 会递归 watch 项目目录，数据建在项目内会导致 EBUSY 崩溃；且要用独立数据目录避免抢用户实例的单例锁、污染用户数据。
8. **聊天内容翻倍 bug**：`llm.streamChat` 结束时的 done 分块携带**全量累计文本**，`chat.js` 若再 `content += chunk.content` 会把回复翻倍。token 分块逐条累加即可，done 分块不能再加。

### 5.3 环境/运行时类
9. **本机配置了代理（127.0.0.1:7897）**，外网必须走代理：LLM/HTTP 请求一律用 Electron `net.fetch`（自动走系统代理），**不要用 Node 原生 fetch**（直连会超时，会话无法聊天）。
10. **deepseek 模型命名 = `deepseek-v4-pro` / `deepseek-v4-flash`**（API /models 实测）。旧名 `deepseek-pro/flash` 会 400。改模型预置后需同步迁移用户数据（settings.json 的 model、sessions/*.json 的 session.model）。
11. **高分屏（Windows 缩放 150%）**：打包版窗口尺寸按物理像素生效，`minWidth:1100` 实际只有 ~733 CSS px，导致 UI 被裁剪。修复：`screen.getPrimaryDisplay().scaleFactor` 乘到窗口 width/height/minWidth/minHeight。注意 dev 版（DIP）与打包版行为不同。
12. **单实例锁 + 数据目录**：main.js 把 userData 重定向到 `D:\Project\Harness\data`（`AI_HARNESS_DATA` 可覆盖）。测试务必用独立数据目录。
13. **CDP 调试**：连 `ws://127.0.0.1:922x` 根路径会失败，必须先 `GET /json/list` 找到 page 的 `webSocketDebuggerUrl` 再连。Electron 上 Browser 域不可用，用 `Emulation.setDeviceMetricsOverride` 模拟窗口尺寸。
14. **PyInstaller 打包导出 exe**：runtime python 忽略 PYTHONPATH，且 stdlib 在 `python312.zip` 内收集不全——用 launcher 脚本注入 site-packages，显式 `--hidden-import`（uuid/webbrowser/argparse/http.server/socketserver/urllib.*/importlib.util/threading/ssl/contextlib/email/mimetypes/base64）；打包工具/缓存/临时目录全部固定在 D 盘（`build-tools`），绝不写 C 盘。

### 5.4 功能实现备忘
15. **多 sandbox 工作区**：`sandboxes.json` 存 `{active, list}`；旧版 `settings.workspaceRoot` 会自动迁移为首个 sandbox（想彻底清除旧工作区需同时删掉 sandboxes 记录和 settings 里的 workspaceRoot，否则下次启动会再迁移回来）。
16. **工作流运行全局状态**：运行在 main 进程（`activeWorkflowRuns` map），前端切页不中断；运行状态提升到 App（监听 `workflow:status/output/done`），WorkflowPanel 挂载时从 props 恢复。
17. **子工作流递归保护**：`runWorkflow` 用**共享调用栈 Set**（进栈/出栈）防循环引用，允许菱形引用（同一子工作流被多个节点引用）。
18. **聊天绑定工作区**：`sandbox.sessionId` 关联每个工作区的独立会话；WorkspacePanel 切换 sandbox 时按 sessionId 加载对应聊天记录。
19. **设置齿轮渲染成巨型 SVG**：`.icon-btn svg` 缺尺寸规则时按 SVG 默认 300×150 渲染 → 显式 `.icon-btn svg { width:17px; height:17px; stroke:currentColor }`。
20. **左下角固定**：侧栏 footer 用 `margin-top:auto` 才能贴底（否则会随侧栏内容上移，工作流页 footer 停在窗口中部）。
21. **工作流画布增强**：框选（marquee 世界坐标矩形 + 中心点命中）、集体拖动（记录被选组 orig 坐标按组平移）、节点缩放（右下角手柄 + `Math.max(170/110, orig+delta/z)` 限制最小尺寸）、Delete 删除选中组（输入框内不触发）；智能体框内工具/技能改为纵向列表（`.wf-links-v`，节点需 `flex-direction:column` + 内容区 `flex:1 overflow:auto` 配合缩放）。
22. **自定义输入/输出节点**：输入、输出节点与智能体节点共用"内嵌工具/技能"渲染（抽成 `renderNodeLinks(n)`）；引擎侧"带工具/技能的节点"在运行时把节点伪装成 agent（`node.type='agent'; node.agentId='assistant'; node.prompt=节点文本或上游拼接`）复用 agent 分支执行，未配置则保持原行为。**注意：输出节点伪装后 `node.type` 已变，最终输出必须按运行前捕获的 `outputIds`（Set）提取，不能再用 `n.type==='output'` 过滤**（JS 端 `outputIds` + Python 端 `output_ids`）。导出侧需同步四处——`checkWorkflow` 校验节点工具/技能、`buildManifest` 把 assistant 加入固化智能体、`copyPyTools` 收集节点 mcp 引用、PY_ENGINE `run_graph` 用 `_node_tool_agent()` helper（input/output 分支共用）。
23. **工具/技能并排**：`.wf-links-v` 用 `flex-direction:row` + 分组 `flex:1 1 0; min-width:0` 均分两列；若分组设固定 `flex-basis`（如 110px）在窄节点（默认 210px）下会 wrap 换行退回上下排，必须均分才能稳定并排。
24. **新建节点只走右键菜单**：用户要求顶部「⌨️ 输入 / 🤖 智能体 / 🔄 子工作流 / 📤 输出」按钮全部取消，只保留画布空白处右键 node-create 菜单（右键菜单已含全部 4 类）；`addNode()` 函数一并删除。
25. **导出两种形式（Python 库 / API 服务）**：导出物新增 `la/__init__.py` 库接口（`La` 类封装 `run_la`，`config` 参数覆盖 LLM 配置），接入说明.md 拆成 `README_HEAD/README_API/README_PY/README_TAIL` 四段按 `target`（all/py/api）组装。**坑：模板字符串内写 markdown 代码围栏（\`\`\`）或反引号必须转义 \`，否则提前终止模板导致 JS 语法错误**；写好的导出模板验证用"提取模板常量 → py_compile + import la 实例化 + README 占位符检查"。
26. **工作流视口位置持久化**：`view` 状态按工作流 id 存 localStorage（`wf-view:<id>`），`loadWorkflow` 时恢复（`setViewSafe`），`createNew` 重置为 `{0,0,1}`；切换页面后重挂载会重新 load 首个工作流并恢复位置。
27. **工程能力开放方案**：见 `工作流能力开放方案.md`（8/20 讨论），六类能力分纵切（节点化：校验/人工确认/工具编排增强）与横切（配置化：上下文策略/状态/可观测性），三阶段渐进落地。**记忆管理不放进画布（不做节点）**——它是横切能力，走工作流级"记忆策略"配置，由 M3 记忆 MVP 提供（memory_* 工具 + md 存储），与阶段三上下文策略复用同一策略引擎，独立里程碑推进。
28. **代码编辑器中文输入 bug（选中位置无法输入中文）**：原实现 textarea 是受控组件（`value={code}`）+ IME 期间 `isComposing` 跳过 onChange——受控组件在组合输入期间会被 React 用旧值回写 DOM，中断/撤销组合输入，选中位置的替换尤其明显。**修复：textarea 改为非受控组件**（不设 value prop，`defaultValue=""` + ref，文件加载后 `taRef.current.value = 内容`），onChange 无条件同步 state（`setCode(e.target.value)`），state 只镜像 DOM 值供高亮层使用；浏览器全权管理选区与组合状态，任意位置 IME 输入正常。
29. **记忆管理（节点级记忆链接 MVP，按文档重构）**：记忆架构 = `data/memory/<架构名>/` 目录空间（policy/ledger/facts/episodes/skills 五文件，memory.js 仓库，IPC `memory:*`，旧版单文件自动迁移）。节点 `node.memory` 数组 → 运行时 tools 并入 `memory_read/write/append/search/forget` + policy 策略摘要注入 system，**执行上下文经 `chat.runChat({toolContext})` → `llm.execTool(name,args,ctx)` → `tools.execTool` 的 ctx.memoryFiles 绑定记忆目录**（scope 默认 write→facts / append→episodes；写操作自动带 `[[txn:…]]` 时间戳并追加 ledger；越权/未绑定/ledger 覆写均返回错误字符串）。Python 导出侧用 `_bind_memory()` 按节点把五工具合并进 registry（`build_tool_schemas` 只暴露 agent.tools 命中的工具，未链接节点不会泄漏记忆工具）。带记忆的输入/输出节点同样伪装 agent（disguise 条件加 `!nodeMemory.length`）。
30. **记忆工作台 + 绑定 + 持久化（阶段 A，8/20）**：记忆页「打开工作台」三栏工作台（文件树/编辑器/属性面板）；`config.json` 差异化配置（默认 scope、ledger/txn 开关、整理工作流）；会话顶栏 + 工作区对话栏**记忆绑定选择器**（会话优先，未绑继承工作区），绑定记录 `boundAt` + 版本游标 `lastArchMtime`；对话前 mtime 检测 → **更新先整理**（`memory.runOrganize`：优先整理工作流，否则默认管家流程 assistant 读全部→去重/分类→memory_* 写回；失败不阻断、游标不更新）。**坑①：工作区对话栏的状态持久化不能只靠 React 局部 state——切页重挂载后 prop 是旧快照**（App 的 activeSandbox 是持久化前的对象，chatModel 读不到），必须在 sandbox 切换/恢复 effect 里**重新 `workspace.sandboxes()` 拉最新记录**再回填模型/目标/记忆绑定；模型/目标在 blur/change 时立即写入 sandbox 记录（有会话再镜像 session）。**坑②：CDP 驱动设置 textarea 值要用 `HTMLTextAreaElement.prototype` 的 value setter**（HTMLInputElement 上没有 value 描述符，会静默失败）；给输入框模拟 blur 要先 focus 再 blur，直接 blur() 在未聚焦元素上不触发事件。
31. **e2e 旧断言过期**：e2e-sandbox.mjs 中「工作流工具栏含子工作流按钮」「智能体节点含上/下端口 isAgent」两断言在 8/19–8/20 改版后已过期（顶部新建按钮删除 + 输入节点也带 `.wf-agent-select`）——维护以 e2e-workflow2.mjs / e2e-exe-wf2.mjs 为准。
32. **PY_ENGINE 模板里的 Python 转义坑（本次发现并修复的潜在 bug）**：PY_ENGINE 是 JS 模板字面量，**Python 字符串里的 `\n`/`\t` 必须写成 `\\n`/`\\t`**，否则 JS 先把它转成真实换行，写出的 engine.py 直接 Python 语法错误（本次 `f.write(line + '\n')` 与 `'[[txn:%s]]\n%s'` 就是踩坑点，PyInstaller/verify 一直没覆盖到真实导出文件的编译，因为 verify 用自定义解析器保留了 `\n`）。**教训：改 PY_ENGINE 后必须真实导出一次 + py_compile 导出物 engine.py**（`m2-wfmem.js` 已内置该检查）。
33. **打包产物 python-runtime/builtin-* 间歇性被写成全零字节（8/20 发现）**：症状 = 打包版报「未检测到 Python」+ `.agent.js/.mcp.js` 加载失败（Invalid or unexpected token）+ `.py` 工具 LOAD_ERROR。根因 = electron-builder 偶发把 extraResources 里**部分文件写成与源同长度但全 0**（如 `python312._pth` 98 字节全 0、`python312.zip` 3.8MB 全 0、全部 6 个 builtin-agent 文件全 0，实测 4215 个文件里 2712 个全 0），且 dev 源完好、fresh 重打一次可能又是好的 → **间歇性**。**解法：打包流程固定加一步校验+修复**——`node scripts/repair-extra-resources.mjs`：对照 dev 源（runtime/python、electron/agents、electron/mcps）逐文件 MD5 比对，缺失/损坏（含全零）则重新复制，最后用嵌入式 python 自检（import encodings/json/uuid/http.server）。**另外 electron-builder 偶发 app-builder.exe Go runtime 崩溃（ERR_ELECTRON_BUILDER_CANNOT_EXECUTE）**：重试即可；崩溃后 `.stage-release\...\app.asar` 会被 TRAE 监视器锁死（禁止删除/改名，只允许覆写）→ 换瞬态目录名（如 `.stage-r2`）继续（**仍是瞬态目录，不建版本目录**）。
34. **checkPython 缓存丢 version + 下载响应头中文文件名非法**：`python-engine.js checkPython` 首次成功返回 `{available,bin,version}`，但缓存命中分支只返回 `{available,bin}` → MCP 面板 banner 显示 `Python 引擎可用 (undefined)` → 缓存命中时也要带 `version`。`api-server.js` 团队下载响应 `Content-Disposition: filename="..."` 里写中文（如 `团队协作规范`）会抛 `ERR_INVALID_CHAR` → 用固定 ASCII 文件名 `team-asset.txt`。
35. **8/21 四连需求（团队转圈/共享资产点不开 + 分类不能删 + 记忆架构自定义 + 记忆要能增删智能体/工具/技能/通信总线、提取记忆）**：
    - **m1 团队"一直转圈"真相**：侧栏团队 nav 用 `nav-spinner`（0.8s 无限旋转动画）表示"运行中"，用户误认为加载卡住 → 改静态 `nav-dot.on` 绿点；同时补上 TeamPanel 启停后 `onStatusChange` 刷新 App 的 `apiStatus`（此前 apiStatus 只在初始化/设置保存时刷新，启停后侧栏指示会残留）。**"共享资产点不开"**：资产摘要 5 行本是纯文本 span → 改为可点击按钮 + `onNavigate` 跳转到对应页面（团队成员间协作用"控制台 📥/📤"）。
    - **m2 分类删除**：`agents.js` 新增 `removeCategory(name)`（从 categories.json 的 list 移除 + 清掉 map/mcpMap 中归属该分类的条目，成员回到「未分类」，代码文件不动；「未分类」禁止删）；技能页原本**没有分类** → `skills.js` 新增整套分类（`data/skills/categories.json`：listCategories/addCategory/setCategory/removeCategory，`list()` 附带 `category` 字段，不影响技能名引用）。UI：AgentPanel/McpPanel/SkillsPanel 分组标题加 🗑（仅非「未分类」），技能卡片加分类下拉（含「＋ 新建分类…」）。
    - **m3 记忆任意文件**：见 3.8「任意文件自由增删」。**注意 `listFiles` 现在递归列出全部非内置文件，bus.md 默认存在**——旧断言（如"listFiles 内置 5 项"）会因多出 bus.md 失效，`m2-memory-a.js` 已按新行为改写。
    - **m4 记忆工作区绑定 + 提取管家**：见 3.8「记忆工作区绑定」「通信总线」「提取记忆管家」。**注意 memory 工具的自定义 scope 越界必须 `resolveInArch` 校验**（execTool 把异常包成 `{error}` 字符串返回，不会 throw）。
36. **`.stage-release` 被 TRAE 监视器锁死（8/21 再犯）**：`fs.rmSync('.stage-release')` 直接 EPERM（上一轮打包残留被 IDE 监视器持有）→ 换瞬态目录名 `.stage-r4` 打包 + robocopy 合并 + 删除，最终产物仍在 `release`（铁律：**绝不建版本目录**）。
37. **teamDownload 用 id 拼路径找不到 agent/mcp 文件（8/21 第二轮发现）**：`GET /api/team/download?kind=agent&name=assistant` 曾直接 `path.join(dir, name)`，但文件名是 `assistant.agent.js` → 404「资产不存在」。修复：先按原样、再试 `${name}.agent.js/py`（mcp 同理）解析。
38. **e2e 用 `select.textContent` 区分节点会误判**：`<select>` 的 textContent 包含**所有 option 文本**——新建的记忆节点架构选择下拉里含「🧠 知识库」选项，`n.textContent.includes('知识库')` 恒真 → 删除"多余节点"的 find 选错。**用结构特征区分**（如读取接口数 = 0）而非文本。**另有 e2e 经验：`team-asset-row` 改版后旧断言过期，维护以 e2e-m1m4b / e2e-exe-m1m4b 为准。**
39. **智能体代码默认分类（`AGENT_CATEGORY`）删除后"复活"（8/21 第三轮发现）**：`agents.removeCategory` 原实现只删 `categories.json` 的 list/map，但 `listCategories()` 会从 agents/pyAgents 的代码默认 `category` 字段重新收集分类 → 只要智能体代码里声明了分类名，删除后分组立刻回来（用户实测"分类文件夹删不掉"）。**解法：categories.json 增加 `removed` 黑名单**——removeCategory 把被删分类记入黑名单 + 清运行时默认值；`listCategories`/`toSummary` 对黑名单内的默认分类跳过（手动 `setCategory` 重新归入可恢复）。回归见 `m3-catdel.js`。
