# 记忆架构工作台（设计方案）

> 依据：`记忆管理-开发文档.txt`、`LAG-harness-整体方案.md` 第四节、8/20 需求（记忆架构像工作流一样在 harness 内自由编辑/管理记忆代码/添加智能体辅助/架构差异化）
> 状态：**设计已定稿；阶段 A（记忆工作台 + 会话/工作区绑定 + 更新先整理 + 选择持久化）已完成并打包 release**。阶段 B（engine.py 记忆引擎）、阶段 C（管家辅助）、阶段 D（导出同步）待推进。
> **8/20 第二轮补充（已实现）**：① 记忆卡片**点击卡片本体**直接进入工作台；② **工作流级记忆**——工作流工具栏「🧠 记忆」选择器绑定 memoryArch，运行时继承规则 = 节点链接 > 工作流级 > 会话/工作区绑定，导出随 manifest 固化（工作区对话选工作流目标时无需单独选记忆）。
> 对比基线：当前记忆只是"数据"（md 文件 + 固定的 5 个内置工具 + 节点链接）；本设计把记忆升级为"一等公民"，对标工作流（列表 → 打开工作台 → 自由编辑 → 保存/测试/整理 → 随导出固化）。

## 一、问题与目标

| 用户反馈 | 现状 | 目标 |
|---------|------|------|
| harness 内部不能操作记忆 | 只能看路径、按文件编辑单个 textarea，无"工作台" | 记忆架构 = 可视化工作台：文件树 + 编辑器 + 属性面板，像工作流画布一样自由编辑 |
| 不同记忆架构不一样 | 所有架构共用固定 5 工具与默认策略 | 每个架构可配置：策略 policy、默认 scope、ledger/txn 开关、专属引擎代码、辅助智能体 |
| 管理记忆的代码 | 记忆工具逻辑写死在 tools.js，不可按架构自定义 | 架构可带"记忆引擎代码"（js/py），自定义/覆盖记忆工具（同智能体 .agent.js 模式） |
| 添加智能体辅助 | 无 | 架构可绑定 0..N 个"记忆管家"智能体（总结/去重/分类/整理），可手动/自动触发 |

**三条底线**（同能力开放方案）：
1. 不配置任何东西 → 行为与现在完全一致（内置 5 工具 + 默认 policy）；
2. 所有自定义随导出固化（config/engine/记忆文件一起进 LA 包）；
3. 人可读可改（全部落为 md/json/代码文件，绝不做黑盒）。

## 二、设计总览：记忆架构 = 记忆空间 + 引擎 + 管家 + 配置 + 绑定

```
记忆架构（一个目录）＝
  记忆空间（md 文件，可自由编辑）
  ＋ 记忆引擎（可选 engine.py，管理/自定义记忆工具）
  ＋ 记忆管家（可选智能体/整理工作流，辅助整理）
  ＋ 架构配置（config.json：差异化行为）
  ＋ 会话/工作区绑定（锁定 + 版本检测 + 更新先整理）
```

对标工作流的"视图"关系：

| 工作流 | 记忆架构 |
|--------|---------|
| 工作流列表（侧栏）→ 打开画布 | 记忆列表（记忆页）→ 打开工作台 |
| 画布（节点/连线/属性） | 工作台（文件树/编辑器/属性面板） |
| 运行 = 图编排执行 | 测试 = 单条消息跑记忆工具；整理 = 跑整理工作流 |
| Ctrl+S 保存 → workflows/<id>.json | Ctrl+S 保存 → memory/<架构>/（md + engine + config） |
| 导出固化（manifest/引擎） | 导出固化（目录整体复制 + engine.py + config.json） |

| # | 模块 | 能力 | 现状 | 目标形态 |
|---|------|------|------|---------|
| 1 | **记忆工作台** | 打开架构进入可视化工作区 | 无（只有管理页弹窗） | 工作台视图：左文件树 / 中编辑器 / 右属性面板 |

| 8 | **导出固化** | 独立运行一致 | 目录复制 + 内置 5 工具 | 目录 + engine（py 直拷 / js 提示）+ config.json 固化；Python 端同构执行 |
| 9 | **会话/工作区绑定** | 记忆绑定对话上下文、锁定、更新先整理 | 仅节点级链接 | 会话/工作区可绑定一个记忆架构并**锁定**；架构被编辑后，**下次对话前先重新读取并整理一遍**再继续（见第四节） |

## 四、会话/工作区绑定与更新迁移（用户核心诉求）

> 依据："记忆管理和对话/工作区绑定；特定记忆架构对应特定记忆存储模式与文件结构；一旦工作区使用某一架构就必须一直用同一个；架构更新后，下一次对话前先读取并重新整理一遍记忆。"

### 4.1 绑定模型

| 项 | 设计 |
|----|------|
| 绑定单位 | **工作区（sandbox）**与**会话（session）**均可绑定一个记忆架构（`memoryArch`）；**绑定入口两处都放**：工作区对话栏 + 会话顶栏。**冲突规则**：会话绑定优先（未绑定时继承所在工作区的绑定；解除会话绑定则回退工作区绑定） |
| 绑定时机 | 首次对话/运行前在选择器里选架构即绑定（记录 `boundAt`） |
| **锁定规则** | 绑定后默认不可直接更换（存储模式/文件结构专属）；提供**「迁移后更换」**：先跑整理工作流把旧记忆转换写入新架构 → 确认 → 重绑（`memoryArch` 更新、`lastArchMtime` 重置） |
| 绑定数据 | `sandboxes.json` 的 sandbox / `sessions/<id>.json` 增字段：`memoryArch`、`boundAt`、`lastArchMtime` |

### 4.2 版本检测与"更新先整理"

- **版本**：架构目录的 `mtime`（每次编辑保存即变化）作为版本；绑定记录上次识别到的 `lastArchMtime`。
- **对话检查点**（`chat.send` 会话对话 / 工作区对话 / 工作流运行，开始前）：

```
开始 → 上下文绑定了 memoryArch？
       ├─ 否 → 正常开始
       └─ 是 → 架构目录 mtime 与 lastArchMtime 对比
              ├─ 相同 → 正常开始
              └─ 已更新 → 先跑「整理」（读全部记忆 → 按新架构重新整理 → 写回）
                          → 更新 lastArchMtime → 再开始对话
```

- **整理执行**：复用工作流引擎——跑「整理工作流」（工作台 ⚙ 配置里可指定；未指定用默认整理流程：读全部记忆 → 交管家智能体总结/去重/分类 → 写回）。整理期间界面提示"正在整理记忆…"。
- **失败兜底**：整理失败不阻断对话（提示 + 仍以旧内容继续），`lastArchMtime` 不更新，下次对话再试。

## 五、界面设计（记忆工作台）

```
记忆页（架构列表，已有）
  └─ 点击架构卡片 → 进入「记忆工作台」视图（视图级切换，类似打开工作流）
       ┌────────────────────────────────────────────────────────┐
       │ 顶栏：🧠 <架构名>   [💾 保存] [▶ 测试记忆工具] [🧹 整理(管家)] [⚙ 配置] │
       ├──────────┬──────────────────────────────┬───────────────┤
       │ 文件树    │ 编辑器                        │ 属性面板        │
       │ 📁 架构名 │ （md 高亮 / 代码高亮，按文件）  │ · 默认 scope    │
       │ ├ policy │                               │ · ledger 开关   │
       │ ├ ledger │   txtaera/pre + hljs          │ · txn 开关      │
       │ ├ facts  │   （复用 CodeEditor 非受控模式）│ · policy 摘要   │
       │ ├ episodes│                              │ · 管家智能体列表 │
       │ ├ skills │                               │   [＋ 添加管家]  │
       │ ├ 自定义  │                               │   🤖 agent名×   │
       │ └ engine │                               │ · 引擎代码入口   │
       └──────────┴──────────────────────────────┴───────────────┘
```

交互规则：
- **文件树点选** → 中间加载对应文件（md 用高亮编辑器；engine.js/py 用代码编辑器）；选中即 `dirty` 标记，`Ctrl+S` 保存写盘。
- **「▶ 测试记忆工具」**：弹窗输入一条消息（如"把 - X 写入 facts"），走当前架构引擎执行对应工具，展示工具调用与结果（不真正改生产文件可加"干跑"开关，MVP 直接执行）。
- **「🧹 整理」**：调起管家智能体（若有），读全部记忆 → 总结/去重/分类 → 写回；无管家则提示。
- **「⚙ 配置」**：差异化配置表单（见六）。

## 六、数据模型（存储布局）

```
data/memory/<架构名>/
├── policy.md / ledger.md / facts.md / episodes.md / skills.md   # 记忆文件（现状）
├── engine.py                                                    # 可选：记忆引擎代码（自定义工具，Python）
├── notes/                                                       # 可选：自定义记忆文件（任意 md）
└── config.json                                                  # 架构差异化配置
```

`config.json` 字段表：

| 字段 | 类型 | 说明 | 默认 |
|------|------|------|------|
| `defaults.writeScope` | string | memory_write 默认文件 | `facts` |
| `defaults.appendScope` | string | memory_append 默认文件 | `episodes` |
| `ledger` | bool | 写操作是否记账本 | `true` |
| `txn` | bool | 写入是否带 `[[txn:…]]` | `true` |
| `policy` | string | 指向策略文件（默认 policy.md） | `policy.md` |
| `helpers` | array | 管家智能体列表 | `[]` |
| `helpers[].agentId` | string | 智能体 ID（agents 库） | — |
| `helpers[].trigger` | string | `manual`（仅手动，MVP）/ `on-write` / `dream`（后置） | `manual` |
| `helpers[].prompt` | string | 管家指令模板（如"总结去重，写入 skills"） | 默认整理指令 |
| `organizeWorkflow` | string | 「整理工作流」id（复用工作流引擎执行整理；空=默认管家流程） | 空 |
| `engine` | string | 引擎代码文件名（engine.py） | 无（内置 5 工具） |

**绑定字段**（存于 sandbox / session，随对话上下文）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `memoryArch` | string | 绑定的记忆架构名（锁定） |
| `boundAt` | number | 绑定时间 |
| `lastArchMtime` | number | 上次对话时识别的架构目录 mtime（用于"更新先整理"检测） |

引擎代码契约（`engine.py`，对标 `.agent.py` / `.mcp.py`）：

```python
# engine.py —— 可自定义/覆盖记忆工具；TOOLS 与内置 5 工具同名则覆盖，新名字则新增
TOOLS = [
    {
        'name': 'memory_tag',               # 工具名（memory_ 前缀）
        'description': '给一条事实打上标签（示例自定义工具）',
        'parameters': {'type': 'object', 'properties': {'tag': {'type': 'string'}}},
        'handler': 'memory_tag',            # 函数名
    },
]
def memory_tag(args, ctx):                  # ctx = { dir, scope_file, config }
    return {'ok': True}
```

- 无 engine 文件 → 内置 `read/write/append/search/forget` 5 工具（现状逻辑，受 config 影响）；
- 有 engine → 内置 5 工具仍然可用，engine 可覆盖同名/新增自定义工具；
- `engine.py` 与导出同构：harness 内经 python 桥接执行，导出时直接复制进 LA 包并注册，PyInstaller 也兼容。

## 七、差异化配置表单（⚙ 配置弹窗）

| 表单项 | 控件 | 写入 |
|--------|------|------|
| 默认写入文件（write） | 下拉 facts/episodes/skills | config.defaults.writeScope |
| 默认追加文件（append） | 下拉 | config.defaults.appendScope |
| 记录账本 ledger | 开关 | config.ledger |
| 写入时间戳 [[txn]] | 开关 | config.txn |
| 策略（读写时机/遗忘规则） | textarea（md，或折叠表单） | policy.md |
| 管家智能体 | 列表 + ＋ 添加（agents 下拉）+ 指令 | config.helpers |
| 整理工作流 | 工作流下拉（复用工作流引擎） | config.organizeWorkflow |
| 引擎代码 | 入口按钮（编辑 engine.py，复用 CodeEditor） | engine.py |

保存后：写 config.json + policy.md；引擎下次运行时读 config 生效（`_load_config(dir)` 合并进 toolContext，`tools.js memoryTool` 读 config 决定 scope/ledger/txn 默认值）。

## 八、引擎与运行时改造点

| 层 | 改造 |
|----|------|
| `memory.js` | + `loadConfig(name)`（读 config.json 合并默认值）；+ `listFiles(name)`（文件树：内置 5 + notes/*.md + engine.py）；+ `writeFileAny(name, rel, content)`（工作台自由编辑）；+ `saveConfig`；+ `archMtime(name)`（版本检测） |
| `tools.js memoryTool` | 读 config（默认 scope/ledger/txn）；无 engine 时保持现状逻辑 |
| 引擎代码加载 | 新增 `electron/memory-engine.js`：加载 engine.py（python-engine 桥接），构造工具表并入 toolContext；工作流节点运行时生效 |
| `workflow.js` | 绑定记忆时传 `{name, dir, config, engineTools}` 进 toolContext |
| 会话/工作区绑定 | `store.js`/`workspace.js` 增 `setMemoryArch(binding, archName)` + 绑定锁定；`chat.js` 对话开始前做"mtime 对比 → 更新先整理 → 更新 lastArchMtime" |
| `exporter.js` | 导出：整体复制目录（含 engine/config/notes）；`_bind_memory` 读 config 字段 + 注册 engine.py 工具；manifest 记录 `memoryCfg` |
| `MemoryPanel.jsx` | 重构为「工作台」：文件树 + 编辑器 + 属性面板 + 测试 + 整理（见五） |
| 整理执行 | `electron/memory.js` 增 `runOrganize(name, opts)`：优先跑 config.organizeWorkflow（工作流引擎），否则默认管家流程（读记忆 → 管家智能体总结/去重 → 写回），返回整理报告 |

## 十、决策结论与待决策点

**已确认（8/20）**：
1. 记忆引擎代码语言：**只支持 Python**（engine.py，与导出同构）；
2. 管家触发：MVP **先手动整理**（更新先整理例外：对话前自动）；
3. 整理形态：**复用工作流引擎**（config.organizeWorkflow 指定整理工作流；未指定用默认管家流程）；
4. 自定义记忆文件：**允许**（工作台可新建 `notes/*.md`）；
5. **会话/工作区绑定 + 锁定 + 更新先整理**（用户补充，见第四节）；
6. 绑定入口：**会话 + 工作区都放**（会话优先，未绑定继承工作区）；
7. 默认整理：未配置整理工作流时交给 **assistant**；
8. 锁定强度：**可迁移后更换**（先跑整理转换 → 确认 → 重绑）。
