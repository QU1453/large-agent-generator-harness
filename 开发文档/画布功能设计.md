# 画布功能设计（记忆画布 / 通用编排画布）

> 目标：让「画布」成为记忆/智能体/工具/文件/通信协议的**可视化编排层**——一张图说清楚
> 「谁调用谁、谁给谁消息、受什么协议保护」，并且**可保存、可运行**。
> 工作流画布 = 同一套节点语义的运行时引擎；记忆画布 = 面向记忆与知识的编排视图，二者能力对齐。

---

## 1. 节点类型

| 节点 | 图标 | 含义 | 关键字段 |
|---|---|---|---|
| 文件节点 | 📄 | 记忆空间里的一个文件（facts/episodes/自定义/引擎代码），双击打开编辑 | `rel`、`kind:'file'` |
| 智能体节点 | 🤖 | 一个智能体，可选中、可配 A2A 安全协议、可经 MCP 链接工具 | `agentId`、`prompt`、`tools[]`、`protocol` |
| MCP/工具节点 | 🔧 | 绑定一个 MCP 或内置工具，作为智能体的调用能力 | `toolId`（内置名或 `mcp:xxx`） |

预留（与《工作流能力开放方案》一致）：子画布节点、条件/循环/并行、人工确认节点、校验节点。

## 2. 连线语义（谁连谁 = 什么关系）

- **文件 → 智能体**：文件内容作为该智能体的输入上下文。
- **MCP/工具 → 智能体**：该智能体**必须经 MCP** 调用此工具（工具随 MCP 注册表执行，不经 MCP 不算合法调用）。
- **智能体 → 智能体**：**必须经 A2A 通信协议保护**：消息封装为 `[[A2A …]]` 信封（含来源身份/时间戳），先过访问控制（允许/拒绝名单），并写审计日志。
- **智能体 → 文件**：智能体输出可写回记忆文件（运行结果落盘）。

## 3. 画布该有的功能（清单）

### 3.1 编辑
- [x] 右键空白 → 新建节点菜单（📄 文件 / 🤖 智能体 / 🔧 MCP 工具），节点落在右键位置
- [x] 节点拖拽移动、右下角缩放（文件/智能体/工具节点统一）
- [x] 节点间连线（↗ 模式点击目标建立），双击连线删除
- [x] 双击节点：文件=编辑内容；智能体=编辑协议；MCP=改工具
- [x] 节点右键菜单：编辑 / 链接工具 / 连线 / 移出画布
- [x] 智能体节点卡片：智能体选择（Trae 式搜索）+ 🔐 A2A 协议（直接在卡片上编辑）+ 🔧 工具（经 MCP 多选）
- [x] MCP 节点卡片：工具选择（内置 + MCP 搜索）
- [x] 底部文件条：点击把文件加入画布并打开编辑；右键管理保护/删除

### 3.2 保存
- [x] 画布**自动保存**（每次改动即写入 `canvas.json`，随记忆空间目录存储）
- [x] 顶栏 **💾 保存画布** 手动确认保存（显示"已保存"）
- [x] 节点坐标/尺寸/连线/协议/工具链接全部持久化，重启恢复

### 3.3 运行
- [x] 顶栏 **▶ 运行画布**：按连线拓扑顺序执行
  - 文件节点 → 输出文件内容
  - MCP 节点 → 声明工具能力
  - 智能体节点 → 收集上游输入 + 经 MCP 的工具 + A2A 协议（校验来源→封装信封→审计）→ 调 LLM → 输出
- [x] 运行结果显示每个节点的输出；协议拦截/错误逐节点标记

### 3.4 安全（硬约束）
- **智能体 → 工具调用必须经 MCP**：工具要么来自 MCP 节点连线，要么显式链接为 `mcp:xxx`/内置工具，统一走工具注册表执行。
- **智能体 ↔ 智能体必须经 A2A 协议**：
  - 身份声明 `identity`
  - 访问控制 `allowedPeers / deniedPeers`（拒绝名单优先；允许名单非空则必须命中）
  - 消息信封 `[[A2A <版本> from=<身份> to=下游 ts=<时间>]] … [[/A2A]]`
  - 审计日志 `data/audit/<记忆名>.jsonl`（message / access-denied / response 三种事件）
  - 协议在智能体卡片上直接编辑，随画布持久化、随导出固化

### 3.5 视图
- [x] 滚轮缩放 / 空白拖拽平移 / 视口位置持久化（按记忆名存 localStorage）
- [x] 右侧信息面板：名称/目录/文件数/画布节点/连线数 + 操作提示，宽度可拖拽
- [x] 连线自适应节点尺寸；节点图标按类型区分

## 4. 数据模型

```jsonc
// <记忆空间>/canvas.json
{
  "nodes": [
    { "id": "policy.md", "kind": "file", "rel": "policy.md", "x": 40, "y": 40, "w": 150, "h": 52, "tools": [] },
    { "id": "mc_ab12", "kind": "mcp", "toolId": "mcp:py_eval", "x": 340, "y": 40, "w": 220, "h": 80 },
    { "id": "mc_cd34", "kind": "agent", "agentId": "assistant", "prompt": "",
      "tools": ["read_file"],
      "protocol": { "enabled": true, "version": "A2A/1.0", "identity": "agent-a",
                    "endpoint": "", "auth": { "type": "none", "secret": "" },
                    "access": { "allowedPeers": ["agent-b"], "deniedPeers": [] }, "audit": true },
      "x": 600, "y": 40, "w": 260, "h": 160 }
  ],
  "edges": [
    { "id": "e1", "from": "policy.md", "to": "mc_cd34" },
    { "id": "e2", "from": "mc_ab12", "to": "mc_cd34" }
  ]
}
```

## 5. 运行引擎语义（electron/memcanvas.js）

1. 拓扑排序（连成环的节点按剩余顺序兜底执行，节点内自行容错）。
2. 逐节点执行：
   - `file`：读文件内容作为输出。
   - `mcp`：登记 `toolId` 到上下文，输出"工具可用"声明。
   - `agent`：聚合上游（文件内容 / 智能体消息 / 工具声明）→ 工具并集（`node.tools` + 直接连入的 MCP 节点工具）→ A2A 校验（仅对上游智能体节点：拒绝名单/允许名单）→ 通过则把上游智能体消息封装 `[[A2A]]` 信封 + 注入协议说明 → `chat.runChat(agentOverride)` → 输出。
3. 协议失败：该节点输出 `[A2A 协议拦截] …`，写 `access-denied` 审计，不再执行 LLM。
4. 所有节点完成后返回 `{ outputs: { 节点id: 文本 } }`，前端逐节点展示。

## 6. 与工作流画布的关系

- 工作流画布（workflow.js）已是同一套语义的成熟引擎：智能体节点 + 节点级工具/技能/记忆链接 + A2A 协议 + 子工作流。
- 记忆画布（memcanvas.js + MemoryPanel）补齐：**文件节点 + MCP 工具节点 + 智能体节点 + A2A 协议 + 保存/运行**，面向记忆知识场景。
- 后续可按需把记忆画布图导出为工作流（节点映射），实现两画布互转。
